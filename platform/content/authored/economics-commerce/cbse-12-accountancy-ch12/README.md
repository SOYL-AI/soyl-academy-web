## Scope
All three syllabus topics (2026-27): **t01** overview of computerised accounting systems — meaning, manual versus computerised, the five components, structure (input → processing → output around a database), features and advantages, limitations, ready-to-use / customised / tailor-made software and the factors in choosing (18 items, 3 shared with t03) · **t02** electronic spreadsheets — cells, formulas, relative and locked references and names, `SUM`, `IF`, `ROUND`, `PMT`, `SLN`, `DDB`, `VLOOKUP`, applied to bank reconciliation, asset accounting (straight-line, written-down value and double-declining-balance schedules), loan repayment schedules and ratio analysis; choosing and reading charts (32 items) · **t03** using a CAS — codification (sequential, block, mnemonic), a four-digit hierarchical coding scheme, groups and ledgers, voucher types, validation, generated trial balance and final accounts, security features (21 items). No topic of this chapter is removed for 2026-27. Software is described generically; no product or brand is named.

**Coding scheme used everywhere** (`questions.mjs` `GROUPS`, notes section 7): four digits; first = primary head (1 assets, 2 liabilities, 3 capital, 4 income, 5 expenses); second = group (11 non-current assets, 12 current assets, 21/22 non-current/current liabilities, 31 capital and drawings, 41 revenue from operations, 42 other income, 51 direct expenses, 52 indirect expenses); last two = ledger (00 is the group itself). **Rounding:** spreadsheet `ROUND` (half away from zero); depreciation, interest and instalments to the rupee; ratios to two decimals.

## Verifier record (what the build computes and asserts)
- **Spreadsheet engine** (`acc.mjs` `Sheet`): every formula shown in a stem, model answer, slide or note table is parsed and evaluated (cell references, ranges, names, `+ − × ÷ ^ &`, comparisons, `SUM`, `IF`, `ROUND`, `PMT`, `SLN`, `DDB`, `VLOOKUP` exact match, `MIN`, `MAX`, `AVERAGE`, `ABS`; circular references and #N/A throw). Every displayed result comes from the evaluation and is asserted against an independent computation (schedules, statements, hand-checked values). `shiftFormula()` produces the copied formulas in the copying items; the broken copy in the copy-error item is evaluated too (two cells give 0, the third throws on text, as the answer says).
- **Bank reconciliation** (`brs()`): each book is summed on its own from an agreed opening balance and a list of entries marked as recorded in the cash book, the pass book or both; the statement's add/less classification must then carry one balance to the other, both ways. Asserted for Pennar (₹1,57,000 → ₹1,79,400), Sabarmati, Ghaghara and Indravati (overdraft ₹1,11,300 per pass book → ₹84,900 per cash book; statement and spreadsheet both reach it).
- **Depreciation** (`slm()`, `wdv()`, `ddb()`): every row asserts opening − charge = closing; straight-line and `DDB` schedules must end exactly at salvage; each `DDB` charge equals the function's value; the last-year cut is asserted where an item relies on it (Tapti, Mandakini).
- **Loans** (`loan()`): instalment = `ROUND(PMT(...), 0)`; every row asserts interest + principal = instalment; the closing balance after the last instalment must be within ₹n of zero — Kosi, Ken, Vaigai and Netravati close at exactly 0; Damanganga (only its first two rows are asked) would leave ₹1, inside the bound. The unrounded `PMT` value quoted for Netravati (₹42,767.23) is computed.
- **CAS** (`cas()`): codes must fit the scheme; vouchers are validated (debits = credits, known codes, date inside the open period, contra uses only cash/bank, receipts debit and payments credit cash/bank); refused vouchers carry generated reasons; saved vouchers are posted to ledgers; the trial balance totals must agree; trading and profit and loss account and balance sheet are built from the code prefixes, every account must land in exactly one statement and the balance sheet must balance. Asserted for Chambal, Bhima (₹8,31,000; net profit ₹88,000; ₹5,98,000), Pench (₹2,49,000), Hasdeo (net profit ₹38,000), Pennaiyar (only P-07 refused) and Sutlej (all three refused, each for its own rule).
- MCQ options built from computed values are distinct (the verify check caught one duplicate distractor during authoring, now replaced).
- `originality --authored` (whole bank): ch12 0 errors, 0 warnings (no reference texts supplied, OA-16). The deterministic verify checks run inside every build (0 flags); the `verify` CLI was not run separately for this unit.

## For a reviewer to double-check
- **Absolute references** are described in words ("a dollar sign before the column letter and before the row number") and demonstrated with **named cells** (`Rate`, `Cost`, `EMI`), because the shared lib forbids the dollar character anywhere (it is the maths delimiter). Students should still learn the locked form with dollar signs; a reviewer may want the lib to allow `$` inside code spans.
- **`PMT` sign convention:** the loan is entered as a negative amount (`-B1`) so the instalment is positive; stated in the fill-blank solution and notes.
- **Loan interest** is rounded to the rupee each period and the instalment is constant; every full schedule shown closes at exactly zero (the engine reports any rounding residual and throws if it exceeds ₹1 per instalment).
- **Final accounts in the CAS examples** are for one month (a business that starts on 1 April 2026) and use closing stock as the only adjustment besides an outstanding expense entered as a journal voucher; presented in statement form.
- The coding scheme (four-digit blocks) is SOYL's own design; schools may teach other numbering, and the items accept any consistent scheme where design is asked.
- Note and deck tables (some sheets have six columns) should be checked at 360 px on staging.
