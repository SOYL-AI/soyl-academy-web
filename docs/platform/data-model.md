# Data model (as built)

> As built: 2026-10-28, from `platform/main` @ 49aa8a4. Source of truth: `platform/db/schema/*.ts` and `platform/db/migrations/`.
> Design intent: [ARCHITECTURE §6](ARCHITECTURE.md#6-data-model-postgresql). Decisions: [ADR-004](adr/004-orm-drizzle.md) (Drizzle, migrations, roles), [ADR-006](adr/006-content-storage.md) (releases), [ADR-010](adr/010-content-api-caching-and-answer-separation.md) (answer separation), [ADR-012](adr/012-test-engine.md) (test engine), [ADR-013](adr/013-ai-gateway.md) (credits), [ADR-016](adr/016-billing-razorpay.md) (billing).
> Package guide: [`platform/db/README.md`](../../platform/db/README.md). Personal data: [`platform/db/PII.md`](../../platform/db/PII.md).

PostgreSQL 17 on Azure (PostgreSQL Flexible Server, Entra-only auth), embedded PostgreSQL 18 locally and in unit tests, `pgvector/pgvector:pg17` in CI. **73 tables and 2 views** across 13 schema files, created by **13 migrations** (0000 to 0012).

## Conventions

| Rule | Detail |
|---|---|
| Ids | uuid v7, generated by the app (`uuidv7()` in `@soyl/db/ids`) with a SQL default `uuid_generate_v7()`. `pipeline_runs.id` is text (readable run id). |
| Time | `timestamptz` only, stored UTC. "Days" (streaks, credit grants) are IST days via `istDay()`. |
| Money | Prices and payments: integer paise. Metered AI and pipeline cost: `numeric(14,4)` paise (single calls cost fractions of a paisa). |
| Enums | `text` + `CHECK`, not Postgres enums. |
| `updated_at` | Maintained by the `soyl_set_updated_at` trigger. Append-only tables have no `updated_at`. |
| Academic year | Catalog and content tables below `boards`/`classes` carry `academic_year`. |
| Foreign keys | Every FK is indexed (asserted by `db/test/schema.test.ts`). |
| Down migrations | Every migration has a hand-written `.down.sql`. Tests run up, down to 0, and up again on fresh and seeded databases and compare schema snapshots. |
| JSON field names | API DTOs use camelCase; content payloads keep their snake_case schemas. |

## Database roles

Created in `0000_foundations` and applied by `soyl_apply_conventions` (DB-1).

| Role | Login | Used by | Rights |
|---|---|---|---|
| `soyl_migrator` | NOLOGIN group role | Migrations and release jobs (`id-soyl-migrator-<env>` in Azure, which is also the Postgres Entra admin) | Owns the schema; runs DDL; seeds the catalog; publishes content. Granted CREATE on the database for the pg-boss schema. |
| `soyl_app` | NOLOGIN group role | API and worker (`id-soyl-api-<env>`, `id-soyl-worker-<env>`) | DML on application tables. **Cannot UPDATE, DELETE or TRUNCATE** `credit_ledger`, `audit_log`, `webhook_events`, `content_budget_ledger`; cannot create tables. |

In Azure the managed identities log in with Entra tokens (no passwords) and are mapped to these roles by the migrate image's bootstrap (`platform/infra/docker/migrate-entrypoint.mjs`). Locally the embedded server uses password auth. Finding S6-L07 (Low) recommends a separate identity for the release job.

## Key invariants

### Answers never reach students (DB-6)

- `questions.body` is the **student-safe projection**. Answers, solutions, marking schemes, rubrics and the keys of case-question children **and their internal-choice alternatives** live only in `question_keys`.
- `splitQuestion` / `joinQuestion` (`@soyl/db/student-questions`) do the split on ingest and restore the exact original. A deep-scan test ingests every real release and checks `questions.body` and the view hold no key-side field or text (`db/test/db6-split.test.ts`).
- The `student_questions` view (`security_barrier`) shows only `published`/`reviewed` rows and hides `live_reserved` items until `embargo_until`.
- Student-facing reads must select `studentQuestionColumns` or read the view, and must never join `question_keys`. The API's content contract test scans every content and practice response for key names and key text.
- History: the alternatives leak was found and fixed in M2 (621f6dc) before any API served it. A related leak through live-mock results while the event runs is open as **S6-H01** (fix in progress on `platform/backend-api/security-fixes-m6`).

### Credit ledger

- `credit_ledger` is append-only for `soyl_app`. Kinds: `grant` (> 0), `reserve` (< 0), `charge` (≥ 0, the unused remainder returned), `refund` (= the reserved amount), `expire` (< 0). Plan top-ups are `grant` rows with action `plan_topup`.
- **Trigger `soyl_credit_ledger_settlement_check`** (0002): a `charge` or `refund` must match an existing `reserve` of the same user and request; a refund returns exactly the reserved credits; a charge cannot return more than was reserved.
- Partial unique index `credit_ledger_one_resolution`: each reservation is resolved once (charge and refund race; one loses).
- One daily grant per user per IST day; `(kind, request_id)` unique.
- Balance non-negative is enforced by the service under a `credit_wallets` row lock, not by a SQL constraint. Credits are authoritative in Postgres; ARCHITECTURE §10's "Redis atomic" balance was not built (ADR-013).
- The worker's `ai.cost-guardrail` job re-checks ledger invariants daily and alerts on any violation.

### Billing

- Webhook processing is exactly-once: `webhook_events.event_id` UNIQUE and `processed_at` written in the same transaction as the effects (the app cannot update the row later).
- `subscriptions.amount_paise > 0`; `entitlements` carry `valid_from`/`valid_until`; the in-force plan is the entitlement with the most daily credits.

### Tests

- One active attempt per (user, test); `responses.client_seq` guards out-of-order autosaves; attempt state checks; ranks and percentiles use `auto_score` only.

```
npm run db -w @soyl/db -- migrate up | down [--to N] | status
npm run db -w @soyl/db -- seed catalog          # boards, classes, subjects, syllabi, chapters, topics, blueprints
npm run db -w @soyl/db -- seed test-users       # fixture users (refused in production)
npm run db -w @soyl/db -- admin bootstrap --email <email>   # DB-7 first admin, audit-logged

```

## Personal data

The DB-5 inventory is [`platform/db/PII.md`](../../platform/db/PII.md): every personal-data column, its retention, and what account deletion does to it. `db/test/schema.test.ts` fails if a column is missing from it. Summary:

- **Account deletion** (`DELETE /v1/me`) anonymises at once, revokes all sessions, deletes `user_mfa` and live ranks in Redis; the worker's `account.purge` job removes the rest within 30 days. Uploaded blobs are not yet deleted with the account (finding S6-M02, open).
- **Unconsented accounts** (AUTH-15): `account.purge-unconsented` is **off** in production while `CONSENT_PROVIDER=unavailable` or `builtin` (otherwise every student who only learns would be deleted after 30 days). Decision pending OA-14.
- **Retention:** AI messages, jobs and uploads 30 days; analytics are first-party and aggregate (no user, device or IP).
- Retention periods are pending counsel (OA-14).
