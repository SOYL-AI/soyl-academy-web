# ADR-007: Diagram rendering — specs as code, validated at stage 4, rendered by our components

- **Status:** Accepted (M1)
- **Date:** 2026-10-26
- **Author:** pipeline-engineer (pipeline side), with design-system's renderer plan (branch `platform/design-system/m1`)
- **Related:** CONTEXT §8 ("diagrams are drawn as code"); ARCHITECTURE §7.2, §8.1 stage 4, §18 item 7; security WEB-6, WEB-7, AC-19, F-012, ASVS 1.3.4; `platform/shared/content/visual.ts`, `svg-allowlist.ts`

## Context

Every lesson, notes page and question can carry visuals. CONTEXT §8 requires diagrams drawn as code (never AI-generated raster images when labels or numbers matter), maths in KaTeX and chemistry formatted correctly. The content is written by a model or a reviewer and then shown to every student on the shared origin, so the visual format is also an attack surface (AC-19: SVG is a scripting format; KaTeX has `\href`; markdown can carry HTML). Students mostly use low-end Android phones, so visuals must be small, crisp at 360 px and readable in dark mode.

## Options considered

1. **Raster images generated by a model.** Rejected by CONTEXT §8: labels and numbers come out wrong, they cannot be checked, and they are heavy.
2. **Raw SVG only.** Flexible, but every diagram is hand-drawn markup that can carry scripts; validation can only be structural; the same chart is drawn differently each time.
3. **Structured specs rendered by our components, with raw SVG as an allow-listed escape hatch** (chosen). Specs are data the pipeline can check for meaning (an expression parses, a segment's endpoints exist, an equation balances); the renderer draws them consistently with theme tokens.

## Decision

### Kinds (contract: `platform/shared/content/visual.ts`)

| Kind | Spec | Use for | Rendered by (design-system) |
|---|---|---|---|
| `svg` | a complete `<svg>` (≤ 60 KB) | apparatus, labelled biology, ray diagrams, circuits | `SvgVisual.tsx`: DOMPurify configured from `svg-allowlist.ts` + `SVG_RULES`, ids namespaced per diagram, client-side, lazy |
| `plot` | axes ranges, `functions[].expr`, points, series, `samples` (default 200) | graphs of real relationships | `PlotVisual.tsx` with its own safe expression parser (`components/platform/ui/visual/expr.ts`) |
| `geometry` | named points, segments, circles, angles, polygons | constructions, triangles, vectors | `GeometryVisual.tsx` (y axis up; coordinates in `[0,width] × [0,height]`) |
| `chem` | `{ equation }` in mhchem notation, or `{ smiles, name }` | reactions; molecules | `ChemVisual.tsx`: KaTeX + mhchem; SMILES via lazy `smiles-drawer` |
| `table` | headers + rows (cells are markdown) | comparisons, observations, atom counts | `TableVisual.tsx` |
| `flow` | nodes + labelled edges, `LR`/`TB` | processes, cycles, decision charts | `FlowVisual.tsx` (switches LR → TB in narrow containers) |

Every visual has `alt` (what it shows, for screen readers) and an optional `caption`. `Visual.tsx` dispatches on `kind`.

### Validation at stage 4 (pipeline, `platform/content-pipeline/src/lint/`)

Stage 4 **rejects** (it never silently strips) so a reviewer sees the problem; the renderer sanitises again before render, and admin save runs the same checks (F-012).

| Kind | Stage-4 check | Severity |
|---|---|---|
| `svg` | Parsed with a strict XML parser (`saxes`), never regexes. Rejected: DOCTYPE (entity expansion, XXE), processing instructions, CDATA, undefined entities, malformed XML; root not `<svg xmlns="http://www.w3.org/2000/svg">` or without `viewBox`; any element outside `SVG_ALLOWED_ELEMENTS` (named reasons for `script`, `foreignObject`, `style`, `image`, `a`, `iframe`, `object`, `embed`, `animate*`, `set`, filters); any attribute outside `SVG_ALLOWED_ATTRIBUTES`; any `on*` handler; `style` attributes; prefixed attributes such as `xlink:href` and extra namespace declarations; `href` other than `#fragment`; `url()` other than `url(#id)`; `javascript:`/`vbscript:`/`data:` anywhere (after entity decoding, so `&#106;avascript:` is caught); `class` values not matching `SVG_RULES.classPattern` (`^diagram-[a-z0-9-]+$`, UI-redress guard); a duplicate `id` inside one SVG; more than `SVG_RULES.maxBytes`. | error |
| `svg` | Hard-coded colours (not `currentColor`, `none`, `var(--diagram-*)`, `url(#…)`); missing `<title>`; an id reused by another diagram in the same deck/notes (the renderer namespaces, but authors should prefix); dangling `#ref`. | warning |
| `plot` | Every `expr` parses with the safe grammar below; it is sampled at 65 points over its domain and must be finite somewhere (error) and should enter the y range (warning); ranges non-empty; points and series finite. | error / warning |
| `geometry` | Every segment, circle, angle and polygon references a defined point; no zero-length segment; coordinates finite. Points outside the canvas are a warning. | error |
| `chem` | `equation` parses with KaTeX + mhchem (`\ce{…}`); atom balance (below). `smiles` uses only the SMILES alphabet with balanced brackets (≤ 500 chars). | error |
| `table` | Every row has as many cells as the header. | error |
| `flow` | Node ids unique; every edge references existing nodes. | error |
| all | `alt`, `caption`, labels, cells and SVG `<text>` go through the text rules (no URLs, HTML, contact details, profanity; KaTeX in markdown cells). | error |

**Plot expression grammar** (identical in `src/lint/expr.ts` and the renderer, so "passes stage 4" means "renders"): numbers, `x`, `pi`, `e`; `+ - * /`, `^` (right-associative), unary minus; functions `sin cos tan asin acos atan sqrt abs ln log exp floor ceil` (`log` = log₁₀, `ln` = natural); implicit multiplication only before a name or `(` (`2x`, `2(x+1)`, `(x+1)(x-1)`, `3sin(x)`); a number directly after a name, constant or `)` is rejected (`x2`, `e3`), and so is `1e3`. Length ≤ 200, nesting ≤ 20. No `eval`, no `Function`, no property access.

**Maths everywhere** (not only visuals): every `$…$`, `$$…$$`, slide `math[]`, notes `formulas[].latex` and chem equation is rendered with KaTeX using the web settings (`trust: false`, `maxExpand: 1000`, `maxSize: 10`) plus mhchem; `\href`, `\url`, `\includegraphics`, `\html*`, `\def`, `\newcommand` and friends are rejected outright. Strings where a JSON escape ate a LaTeX backslash (`ce{`, `frac{` without `\`, or a form-feed/tab/CR where `\frac`/`\times`/`\rightarrow` was) are errors.

**Atom balance:** every `\ce{… -> …}` and chem visual equation is balanced atom by atom (groups, hydrates `CuSO4.5H2O`, state symbols, charges, `^`/`v` gas/precipitate marks and arrow conditions handled; equations with placeholders such as `xH2O` are skipped). A deliberately unbalanced equation is allowed when the surrounding text marks it — the same slide, question stem, flashcard or notes section says "skeletal", "unbalanced", "not balanced", or the imperative "Balance …" — or when it is a wrong option of an objective question. This needs no contract field; it also nudges authors to tell the student the equation is not balanced yet.

### Rendering on the web (design-system, recorded here for parity)

- Renderers live in `components/platform/ui/visual/` and are the only places allowed to use `dangerouslySetInnerHTML` (WEB-6), after sanitising.
- Theme: `currentColor` and `--diagram-accent | --diagram-muted | --diagram-fill` (`DIAGRAM_PALETTE`), defined for light and dark; classes `diagram-accent`, `diagram-muted`, `diagram-fill`, `diagram-label`, `diagram-thin`. Other classes are dropped at render and rejected at stage 4.
- Raw SVG ids are prefixed per diagram and `#refs`/`url(#…)` rewritten, so several diagrams can share a page.
- Heavy renderers (SMILES, KaTeX CSS) are lazy-loaded only on pages that need them (ARCHITECTURE §3.2, §16).

### Pipeline-side generation rules

Templates ask for the most specific kind that fits (structured spec first, raw SVG only for apparatus/biology/optics/circuits), describe the allow-list and palette in the prompt, and require `alt` that states the information shown. The mock provider emits one valid example of every kind, so the whole chain is exercised offline.

## Consequences

- Visuals are checkable and consistent; a release containing `<svg onload>` or a `javascript:` link fails stage 4 (AC-19 verification), covered by the XSS corpus in `content-pipeline/test/lint-rules.test.ts`.
- Two parsers (pipeline, renderer) must stay in step for the plot grammar and the SVG rules. The data (`svg-allowlist.ts`, `SVG_RULES`) is shared; the grammar is specified above and tested on both sides. A change to either needs an update here.
- No real hue tokens yet: real-world colours (blue solution, yellow precipitate) are carried by labels. Adding semantic hue tokens (exemplar recommendation 5) is a design-system change plus an addition to `DIAGRAM_PALETTE`.
- New runtime dependencies in the pipeline: `saxes` (strict XML parser, 1 small dependency) and `katex` (the renderer the web uses; same rules both sides). Both had no advisories at install (`npm audit` clean).
