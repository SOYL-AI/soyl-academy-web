## Deviations from ARCHITECTURE §6

1. **`role` is on `users`**, not on `profiles`. It is the column of Better Auth's admin plugin, so there is one source of truth for authorisation. `profiles` holds display name, board, class, school, city and locale.
2. **Questions store no answer data** (DB-6). `answer`, `solution`, `marking_scheme` and the case-question children's keys are in `question_keys`. `questions.body` is the student-safe projection. New columns: `pool`, `embargo_until`, `is_current`, `key`.
3. **Tests reference question version rows.** `tests` and `test_items` point at `questions.id`, which is one version (D-023). `tests` has `(key, version)` and stores the TestDefinition JSON.
4. **Append-only tables have no `updated_at`**: `credit_ledger`, `audit_log`, `webhook_events`, `content_budget_ledger`, `analytics_events`. The app cannot update them, so `webhook_events.processed_at` is written in the same transaction as the event's effects.
5. **`pipeline_runs.id` is text** (the pipeline's readable run id). Added `pipeline_items` and `content_budget_ledger`, plus the `content_budget` view.
6. **Metered AI and pipeline cost is `numeric(14,4)` paise** (`ai_requests.cost_inr_paise`), because single calls cost fractions of a paisa. Prices and payments are integer paise.
7. **`content_reports` is in ops** (as briefed), not content.
8. **`blueprints` store parsed JSON** (`definition`) and `source_path`, not raw YAML text.
9. **`boards` and `classes` have no `academic_year`.** They are reference data. Everything below them is year-scoped.
10. **`analytics_events` has no user, device or IP column** (D-014).
11. **Extra tables**: `leaderboard_snapshots` (§6 says "snapshotted weekly") and `syllabus_versions`, which holds per-file metadata and a content hash.
12. **Credit ledger semantics are now fixed in the schema**: signed deltas (grant > 0, reserve < 0, charge ≥ 0 as the unused remainder, refund = reserved, expire < 0); one daily grant; one resolution per reservation; plan top-ups are `grant` with action `plan_topup`.

## Known gaps / follow-ups

- **pgvector is only tested in CI.** One schema test is skipped locally. infra-azure has been sent the CI service requirements: pgvector image, superuser `TEST_DATABASE_URL`.
- **Phone OTPs (AUTH-4, backend-api).** Better Auth's `phoneNumber` plugin stores `code:attempts` in plain text in `verifications.value`. backend-api must supply `sendOTP` and `verifyOTP` that store an HMAC instead. Email OTP is hashed (`storeOTP: 'hashed'`, tested).
- **Session tokens (DB-4).** Better Auth stores them unhashed and has no option to change that. The mitigation (signed cookie, `bearer` plugin kept off) is documented in the README.
- **Credits concurrency (AC-07)** is Redis-side (ai-gateway, M4). The database provides the uniqueness and settlement invariants; there is no balance-non-negative constraint in SQL.
- **CISCE catalog** was not on `platform/main` yet. The seed picks up `platform/catalog/cisce/subjects.yaml` and its syllabi automatically, and the tests compare against whatever files exist.
- **Blueprints**: no blueprint YAML exists yet, so the seed loaded 0. The loader and schema are in place (`**/blueprints/*.yaml`, validated with the shared `Blueprint` schema).
- **Account deletion and purge jobs** belong to backend-api. Their exact behaviour is specified in PII.md.
- `TEST_PHONE_PREFIX` (`+91555000`) should move to `platform/shared/config/security.ts` once that file exists (GEN-2/GEN-3).
